
# Ray Core

Ray provides a distributed execution model on top of compute resources such as CPUs and GPUs.

---

## Ray Task and Ray Worker

* A `Ray Task` is executed asynchronously by a `Ray Worker` process.
* Each `Ray Worker` is a Python process.
* By default, a `Ray Task` requests 1 logical CPU resource. 

Note: A Ray CPU resource is a *logical* scheduling resource. It does not represent a specific physical core or logical CPU.

## Ray Actor

Use a `Ray Actor` when state needs to persist across remote method calls.

* A `Ray Actor` is essentially a stateful worker.
* When an Actor is instantiated, Ray creates a dedicated worker process for that Actor.
* The Actor instance remains alive in that worker process.
* Actor methods can access and mutate the Actor's persistent state.

```text
Dedicated Ray Worker Process
└── Actor Instance
    ├── State
    ├── method()
    └── method()
```

---

## Ray Scheduler vs OS Scheduler

The responsibilities of the Ray scheduler and OS scheduler are different.

**Ray Scheduler**

* Determines which node should run a Task or Actor.
* Uses logical resource requirements such as:

  * `num_cpus`
  * `num_gpus`
  * custom resources

**OS Scheduler**

* Determines which logical CPU executes a process or thread.
* May move threads between logical CPUs during execution.

```text
Ray Task → Ray Scheduler → Select Node → Ray Worker Process → OS Scheduler → Logical CPU
```

## CPU/GPU Resources

**CPU**

Ray does not provide strict CPU isolation or CPU pinning by default.

Therefore:

* Resource requirements do not strictly limit actual physical resource usage.
* Developers should choose resource requirements that reasonably reflect actual resource usage.
* Incorrect resource declarations can cause oversubscription.

Ray resource requirements such as `num_cpus` are used primarily for scheduling and admission control.

For example:

```python
@ray.remote(num_cpus=4)
def work():
    ...
```

means:

```text
Treat this Task as consuming 4 logical CPU resources for scheduling purposes.
```

It does not mean:

```text
Pin or restrict this worker process to 4 physical CPU cores.
```

**GPU**

GPU resources follow a similar scheduling model.

For example:

```python
@ray.remote(num_gpus=1)
def inference():
    ...
```

means that Ray reserves 1 logical GPU resource for that Task. 

Unlike CPU resources, Ray also assigns GPU device visibility to the worker, typically by setting `CUDA_VISIBLE_DEVICES`.

However, a GPU resource request does not by itself guarantee exclusive use of GPU compute or GPU memory.
